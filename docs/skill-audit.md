# Аудит навыков для проекта «Обед»

Каталог доступных навыков рассмотрен по назначению. Детально изучены применимые рекомендации по интерфейсам; у больших image-first руководств отдельно проверены область применения и метод. Сами навыки — разные авторские подходы, местами противоречащие друг другу, а не единый стандарт качества. Не следует механически включать их все.

| Навык | Применимость и решение |
|---|---|
| sites:sites | Основной процесс создания, приватной публикации, источников и D1 |
| frontend-design:frontend-design | Применён: предметная фотография, самостоятельная идентичность, осмысленный текст, сдержанность и мотивированная анимация |
| redesign-existing-projects | Применён: аудит существующего интерфейса, сохранение функциональности, focus/active/error/empty состояния, размеры и ритм |
| design-taste-frontend v2 | Рассмотрен: полезен аудит и сохранение токенов; сам исключает многошаговые формы из своей специализации. Эффектные landing-паттерны не переносились в checkout |
| design-taste-frontend-v1 | Устаревший совместимый вариант; нет основания заменять текущий подход старой версией |
| high-end-visual-design | Рассмотрен: производительность, easing, цельность. Сплошные стеклянные оболочки, магнитные кнопки и театральное меню не подходят быстрому заказу |
| minimalist-ui | Рассмотрен: спокойные поверхности и иерархия. Жёсткая чёрно-белая палитра и workspace-типографика не заменяют пищевой бренд |
| gpt-taste | Рассмотрен: предостерегает от длинных заголовков и пустот. Случайная композиция, принудительная AIDA и GSAP pinning не нужны каталогу |
| stitch-design-taste | Рассмотрен как пример структуры DESIGN.md; Google Stitch здесь не используется. Требование бесконечного движения отвергнуто как неподходящее сценарию |
| industrial-brutalist-ui | Рассмотрен по назначению и правилам: техническая моноширинная эстетика, CRT и военные панели расходятся с продуктом |
| image-to-code | Рассмотрен метод image-first секционных макетов; текущая задача — работающий конструктор и его корректировка, а не пакет растровых макетов. Интерфейс остаётся реальным HTML |
| imagegen-frontend-web | Рассмотрен метод отдельных растровых концептов секций; не применялся как workflow, потому что потребителю нужен рабочий магазин, а не 6–8 картинок страниц |
| imagegen | Применён встроенный ImageGen для фирменного hero и 12 самостоятельных блюд в одном техническом atlas-ассете |
| brandkit | Изучены принципы смыслового знака, единой палитры и последовательности. Не генерировалась отдельная имиджевая доска вместо интерфейса |
| skill-creator | Применён для глобального design-reference-motion; валидация пройдена |
| anatomy / visualize | Объяснительные интерактивные фигуры; не нужны в процессе заказа обеда |
| Figma / SwiftUI / Code Connect / shaders | Нужны при заданном Figma-проекте, iOS-реализации или импорте; назначения отсутствуют |
| Three.js / игровые / camera / dialogue / level / puzzle / performance | Для игровых и 3D-сцен; не нужны для заказа еды |

| spreadsheets / presentations / documents / pdf / template | Для соответствующих файлов, не заменяют разработку интерфейса |
| Hugging Face / ML / AWS | Для ML-моделей, обучения и инфраструктуры; не относятся к продукту |

## Принятый порядок решений

1. Прямые требования пользователя: 390 ₽, четыре названные категории, чёрные контейнеры, самостоятельное переключение, выбор выделением карточки.
2. Стабильная геометрия и независимость действий выбора/состава.
3. Доступность, читаемость и ясные состояния оформления.
4. Самостоятельный бренд и прикладные анимации.

Подробная карта каждого блока, элемента и его движения находится в DESIGN.md. Переиспользуемый глобальный навык design-reference-motion создан отдельно от конкретной цены, меню и названия проекта.
